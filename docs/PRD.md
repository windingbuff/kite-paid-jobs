# 07 · 付费长任务组件

PRD 1.0 · 2026-10-18 · 履约基础设施 · 第二批，先做互通 PoC  
状态：设计提案，未实现/未付款/未提交。先读[总体接入设计](../总体接入设计.md)与[接口事件约定](../接口与事件约定.md)。

## 1. 用户与真实场景

**用户：**提供文档处理、浏览器批处理等耗时服务的卖方，以及需要恢复任务的 Agent 客户端。

**第一次使用：**Agent 已购买一个耗时文档任务，等待时宿主退出；重启后仍能凭原付款身份查询并领取结果，不重新生成或付款。

**问题：**付款成功、任务入队、执行完成和结果领取是不同状态。任务中断后容易重付，结果链接又可能泄漏给其他钱包。

**Kite 接入价值：**Passport 当前已描述 Job→Poll→Retrieve 和零付款 SIWX 取件。本项目补卖方持久任务、原付款人权限、恢复及对账，不能宣称创造了异步 x402 协议。

## 2. MVP 范围

**P0，首版必须完成：**

- 首版一个固定价格、固定资源上限的任务类型；购买前明确交付合同、预计时间、保留期及失败处理。
- 付款验证后持久保存任务与 outbox；确认结算后才派发付费任务，队列失败前不结算。
- 提供稳定 job/status/result；付费主体与取件身份绑定，通过经过验证的 SIWX 实现免费身份取件。
- 客户端持久化原 session 与 job，轮询有退避与上限；时间到显示 unresolved，不能自动重买。

**P1，有真实反馈后再做：**

- Webhook 仅作可选通知，不作为唯一交付证据；加入签名与去重。
- 在明确退款与账务接口后增加人工处理辅助，不宣称自动原生退款。

**首版排除：**不建立新通用异步标准、不承诺链上原生 escrow/自动退款、不将一次批准当无限期后台授权。

## 3. 完整用户流程

1. 请求报价并批准会话，授权范围同时包含提交与状态/取件路径。
2. 用户付费提交；服务确认可接受任务并持久化，成功结算后返回 job_id 和同源 pollUrl。
3. worker 根据已确认结算的 outbox 开始任务。
4. 客户端带原 session 轮询；需要身份时处理 SIWX，不追加货币付款。
5. 任务完成，验证原付款钱包后返回实际产物；客户端中断后使用原 job 恢复。
6. 执行失败标 paid_unfulfilled 并进入承诺的人工处理流程；轮询超时只记 unresolved。

## 4. Kite 能力接入

| 官方能力 | 接入方式 | 保存与验证 |
|---|---|---|
| 异步购买 | Passport session execute 的 async paid goods 流程 | job_id、pollUrl、原 session、实际付款凭证 |
| 免费身份取件 | x402 v2 SIWX；由实际可互通库实现 | 原付款钱包证明，response protocol=siwx/amount=0 需真实核验 |
| 卖方交付 | x402、持久队列、产物库 | verify→接单持久化→settle→worker；接单成功不冒充任务已完成 |

**接入前置：**所有涉及真实付款的路径先完成 G0，固定 network/asset/facilitator/CLI/账户环境；见总体接入设计。真实身份或 Runtime 不可得时明确 blocked，不能用 mock 替代。

**授权边界：**应用与业务权限自己验证；Passport 的 passkey 批准保留给真实用户；本轮 PRD 编制不发起任何授权或支付。协议实例、金额、会话和示例均以现场预检与实际输出为准。

## 5. 接口与数据

**拟提供接口：**POST /v1/jobs 提交一次已报价任务；GET /v1/jobs/{id} 查询；GET /v1/jobs/{id}/result 身份取件；响应形如 {job_id,status,pollUrl,result:null|artifact}。这是自建稳定协议，不能把任意 input URL 当输出产物。

**核心对象：**Job、JobSpecVersion、Purchase、PayerBinding、Outbox、ExecutionAttempt、Artifact、Retrieval、ResolutionCase。付款与履约各有独立状态。

operation_id、付款证据、业务版本及产物按公共事件契约关联。接口/包名属于本项目设计，不代表官方已经发布同名能力。

## 6. 状态与恢复

付款 VERIFIED → SETTLEMENT_PENDING → SETTLED/UNKNOWN；任务 ACCEPTED → QUEUED → RUNNING → SUCCEEDED/FAILED；领取 AVAILABLE → RETRIEVED/EXPIRED。UNKNOWN 时不发任务、不新收费。

- pollUrl 先做标准 URL 解析，再严格验证 scheme/host/port 同源；换域、换端口、重定向均需拒绝或重新验证。
- SIWX 库与当前 Passport 无法互通就阻塞此路径，不能改成公开下载或未经验证的 wallet header。
- 付款后 worker 失败不得显示全部成功；退款/补偿必须按明确条款与实际获批动作执行。任务过期不抹除交易与异常证据。

任何付款未知均不能通过换 key 自动重买；任何产物恢复都需要原权限。测试桩中的假付款不产生真实交付承诺。

## 7. 开发任务拆分

- 07-T01：先验证实际网络上的 Passport 异步购买和 SIWX 示例。
- 07-T02：固定任务合同、价格与失败处理规则。
- 07-T03：实现付款/outbox/worker 状态及恢复。
- 07-T04：实现受权轮询与取件、产物保留。
- 07-T05：联调客户端恢复、对账和人工失败处理。

**投入粗估：**6–8 人周。先做 M0 兼容与样本验证，再做独立核心、真实互通及发布；外部批准、环境开通和审核不计入可承诺工期。

## 8. 界面与使用体验

任务列表区分“已付款、运行中、可领取、未决、失败待处理”，详情含原付款和交付记录。

在需要用户决定时展示价格、范围、权限和失败状态；普通产品页面不堆协议实现细节，技术证据留在诊断/报告页。

## 9. 验收与演示

下面是目标，尚未运行或达成。

- J01：同 job 中断恢复不触发新购买，取件实际无新增费用。
- J02：其他钱包、过期签名、重放挑战和越权产物访问被阻止。
- J03：覆盖结算响应丢失、outbox 重放、worker 崩溃、任务失败、轮询超时与产物到期。
- J04：G0 通过后跑真实 Passport 购买与 SIWX 取件；仅看到 202 不写成实际产物已交付。

**完整演示：**真实购买任务后关闭客户端，再用原 session 恢复并通过 SIWX 取件；对比另一钱包被拒绝的结果。

**试用观察：**恢复成功率、重复购买事件、已付未交付积压、取件无故追加费用事件。

## 10. 提交与独立性

组件/实际服务贡献；不是天然独立 Bounty 类别。当前目录是否接受异步端点和定价语义需另核验，初期可先依附一个真实服务交付。

项目核心包括本 PRD 定义的模型、业务引擎/状态/断言与样本；支付和基础依赖可正常共享，不复制其他参赛实现换名。EC 映射、活动审核与真实贡献是否被统计分别跟踪，不用本 PRD 保证收录。
